04 How it stays smooth

    
The browser moves the pieces. The script only says where.

    
A phone in Low Power Mode lets a page's script run about 30 times a second, unevenly. A board that moves its pieces from script, frame by frame, is held to that. Lightsquare writes the new place of a piece once and hands the slide to the browser.

    

      
One state
The position, the marks and what may move are one plain object. Your app and the player's finger both change it.

      
Compare
The new state is compared with what is on screen. A piece that stays is not touched; a piece that moved keeps its element.

      
A few writes
A move is five small writes to the page, whatever the position. No measuring, no timers, no animation loop.

      
The browser slides
The piece gets a new transform and a CSS transition. From there no script runs until it has arrived.

    

    
    
      
  • Transforms onlyA moving piece changes its transform and nothing else.
    • 
      
  • Nothing at restA board that is not moving asks for no frame, no paint, no timer.
    • 
      
  • No chess rules insideYour app says which moves are allowed. The board never judges.
    • 
      
  • Any size, no scriptPlaces are fractions of the board's width. A resize runs nothing.
    • 
      
  • One measure per dragThe board is measured once, when the press begins.
    • 
      
  • Every rule has a testThe rules are checked against the source and in real browsers.

06 Use it

    

      


import { lightsquare } from "lightsquare";
import { shapes } from "lightsquare/shapes";
import "lightsquare/lightsquare.css";
import "lightsquare/pieces/cburnett.css";

const board = lightsquare(element, {
  movable: "white",
  targets,                      // Map: where each piece may go
  onMove({ from, to }) {
    // your chess rules decide; then confirm or take back
    board.set({ position: fenAfterTheMove });
  },
});

board.use(shapes({ arrows: [{ from: "e2", to: "e4" }], draw: true }));
